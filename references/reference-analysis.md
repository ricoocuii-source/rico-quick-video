# 抖音 GitHub 榜单博主：技法拆解与全自动复刻方案

样本：`/private/tmp/dy-videos` 三条视频（GSAP skills / uiverse galaxy / nuwa-skill），每条 39～42 秒，30fps，HEVC，1776/1896×1080。

## 一、结论

1. 视频不是"纯脚本自动生成"，是**固定模板 + 半自动流水线**：Screen Studio 类工具录屏 → 剪映做 TTS/字幕/贴纸/转场。
2. 三条视频结构、时长、镜头语言、贴纸素材完全一致，说明博主有一套固定的"剪映草稿模板"，每期只换录屏和口播稿。
3. 这条流水线可以 100% 用代码复刻，且关键环节（选题、研究、截图/录屏、写稿、TTS、合成）都有现成工具，唯一需要人工的是最终审核。

## 二、逐帧证据

### 1. 固定叙事骨架（三条完全一致）
| 时间 | 段落 | 画面 | 口播句式 |
|---|---|---|---|
| 0–3s | 钩子 | 黑底 3D 翻页动画 + 大字 | "前端圈又炸了！/ 科技圈直接炸锅！/ 演都不演了！" |
| 3–9s | 报名字 | 官网首页 → 模糊拉镜 → GitHub 仓库页，箭头指向 repo 名和 Star 数 | "记住这个名字，在 GitHub 上已狂揽 X 万 Star" |
| 9–13s | 一句话定位 | 鼠标拖选 About 描述 | "是目前规模超前的开源 UI 库" |
| 13–30s | 核心卖点巡览 | README/官网逐段滚动+缩放，红圈、箭头、大字花字弹出（"即拷即用！""五层剥离法！""全部免费！"） | 每 2～4 秒一个卖点 |
| 30–35s | 三点总结 | 绿色六边形序号 01/02/03 逐个弹出 | "社区产出 / 免费商用 / 30 万贡献者" |
| 35–40s | CTA | 仓鼠"点赞 关注 评论"贴纸 | "感兴趣的兄弟赶紧冲，觉得硬核点赞关注，下期见！" |

场景切换点（ffmpeg scene>0.35）：GSAP 条 15 个、galaxy 条 4 个、nuwa 条 7 个，卖点数量决定切镜数，其余节奏一致。

### 2. 录屏层（Screen Studio 特征）
- 浏览器窗口带圆角、悬浮在**模糊壁纸**上（macOS 桌面壁纸虚化），不是原始录屏。
- 光标被单独渲染放大（I 型光标高约 150px），跟随光标自动推近/拉远，缩放带缓动。
- 缩放时画面出现横向运动模糊（"拉镜"），放大到超过源分辨率会糊，说明是后期缩放，不是重新录制。
- 英文站点显示为中文（uiverse 的"最大的开源用户界面库""按钮/复选框"），是 **Chrome 页面自动翻译**，不是站点自带中文。
- 操作动作：hover、点击、拖选文字、滚动，全部与口播同步，每个卖点停留 2～4 秒。

### 3. 剪映层（后期特征，全部是剪映内置素材）
- 字幕：白字 + 蓝紫描边，关键词黄字放大（剪映"智能关键词高亮"），**打字机动画**带白色方块光标"▌"，出现在字幕结尾。
- 花字：大号黄底黑描边斜体（"即拷即用！""搜索全网蒸馏！""全部免费！"），带弹出动画。
- 贴纸：像素风黄色箭头、红色手绘圈、绿色六边形序号 01–05、仓鼠"点赞关注评论"、开头 3D 翻页。
- 转场：模糊拉镜（推近/横移带模糊），配合镜头切换。
- 右上角常驻文字："纯科技知识分享，无任何第三方站外引流"。
- 开头黑底大字钩子 + 结尾荧光绿/仓鼠 CTA。

### 4. 音频层
- 口播全程无 0.3s 以上停顿（三条视频均为 0～1 处），语速约 5 字/秒，onset 约 7.8/秒。
- 全程压一层低音量节奏型 BGM（频谱图可见规律竖条）。
- 基频中位数约 340Hz，明显高于常规人声，符合剪映 AI 配音提速或变调后的特征。
- 判断：口播是 **TTS（剪映 AI 配音）或人声经"去停顿+提速"处理**，两者听感在此已无差别，复刻时直接用 TTS 即可。

### 5. 文案层（LLM 可完全接管）
口播稿本质是"README 卖点抽取 + 抖音话术模板"：
- 钩子一句（圈子 + 炸了）
- 名字 + Star 数（数字必须具体）
- 一句话定位（直接引用 About）
- 3～6 个卖点，每个 8～15 字，动词开头，带一个可以放大的关键词
- 三点总结（序号化）
- 固定 CTA

## 三、全自动复刻方案（每天只给一个 GitHub 链接）

```
[输入] GitHub URL（或 trending 榜单自动选 1～2 个）
   │
   ▼
① 研究 Agent（Claude + Playwright MCP）
   - 抓 README / About / Stars / 官网链接 / demo 链接
   - 自主浏览官网、点开 demo、README 内锚点
   - 输出 research.json：卖点列表（每条含：文案、页面 URL、要指向的 DOM 选择器/文字、动作类型 hover/click/select/scroll）
   │
   ▼
② 写稿 Agent（Claude）
   - 按第二节的模板生成 script.json：段落、口播文本、关键词、花字、序号点、每段目标时长
   │
   ▼
③ TTS（本地 edge-tts 已安装，或 火山/MiniMax/CosyVoice 换更像抖音的声音）
   - 逐句合成 → 拿到每句精确时长和字级时间戳
   - 时长反向决定每个镜头停留时间
   │
   ▼
④ 自动"录屏"（Playwright，无头 Chromium，2560×1600）
   - 逐卖点执行：goto → 等待 → 自动翻译（可用 Chrome 翻译或注入 LLM 翻译后的 DOM 文本）→ 移动鼠标 → hover/click/拖选 → 截图序列或 recordVideo
   - 同时记录每帧光标坐标 + 目标元素 bbox，写入 timeline.json
   - 光标不用真录，后期按坐标重绘放大光标（和 Screen Studio 一样）
   │
   ▼
⑤ 合成（HyperFrames 或 Remotion，React 声明式）
   - 背景：模糊壁纸 + 圆角窗口
   - 摄像机：按 timeline 里的 bbox 做 zoom-to-target，缓动 + 模糊拉镜转场
   - 光标层：按坐标插值绘制放大光标
   - 字幕层：按字级时间戳做打字机 + 关键词黄字
   - 贴纸层：箭头/红圈/序号/花字/仓鼠 CTA，全部做成组件，按 script.json 触发
   - 音频：口播 + BGM ducking
   - 渲染 1920×1080 30fps → mp4
   │
   ▼
⑥ 质检 Agent
   - 抽帧 + 转写，核对字幕/口播/画面是否对齐，卖点是否真实存在于页面
   - 不通过回到 ④ 重录对应片段
   │
   ▼
[输出] final.mp4 + 封面 + 标题/文案，人工看 40 秒后发布
```

### 可行性判断
| 环节 | 可自动化 | 工具 | 风险 |
|---|---|---|---|
| 选题（trending 抽 1～2 个） | 是 | GitHub API / agent-reach | 低 |
| 自主研究、下钻主页、截图 | 是 | Claude + Playwright，你现在就有 Chrome MCP | 中：需限制步数和站点 |
| 写口播稿 | 是 | Claude，模板固定 | 低，需要话术样本喂给它 |
| TTS + 字级时间戳 | 是 | edge-tts（已装）/ 火山引擎 | 低；抖音味声音需付费 API |
| 自动录屏 + 光标动作 | 是 | Playwright 脚本化 | 中：拖选文字、翻译需要写稳定的动作原语 |
| Screen Studio 式缩放、模糊拉镜 | 是 | HyperFrames/Remotion 动画 | 低，一次写好复用 |
| 剪映风字幕/贴纸 | 是 | 自己画组件（SVG/PNG） | 低；贴纸需自制或找可商用素材 |
| 字幕 | 你说可以先略过 | 字级时间戳直接生成 | 低 |
| 终审 | 否 | 人看 40 秒 | 必须保留 |

结论：**能做到全自动流水线**，输入一个 URL 到输出 mp4 全程无需人手。真正难点只有两个：④ 的浏览器动作稳定性（页面结构千差万别，要让 agent 先"探路"再"录制"），以及贴纸/声音的"抖音味"（这是素材问题，不是技术问题）。

## 四、建议的落地顺序
1. 先做 ⑤ 合成器：拿一段手工 Playwright 截图 + 一段 edge-tts，把"模糊壁纸 + 缩放 + 打字机字幕 + 箭头"跑通，验证画面像不像。
2. 再做 ④ 自动录屏：定义 5 个动作原语（goto/scroll_to/hover/click/select_text），输出 timeline.json。
3. 再接 ①② 研究和写稿 agent，用三条样本的口播稿做 few-shot。
4. 最后接 ⑥ 质检和定时任务。
