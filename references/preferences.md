## 协作节奏
- **触发任务后的第一件事：出口播稿。** 读完 README / 官网就直接写 `script.json` 并把口播稿贴进对话，**然后停下等他确认**，不许先去采镜头、配音、渲染。文案他会亲自调好几轮，**改完的版本就是新规则**。（2026-09-13 他专门要求把这条写死。）
- **他说「先出口播稿和静帧」时，可以出内容确认静帧**（给人核对卖点），仍禁止正式 `capture.py` / `tts.py` / 渲染。确认静帧 ≠ 生产镜头。
- **他说「用我的口播稿，其他按你推荐」= 闸口过了。** 直接按推荐采镜头、配音、渲染，不要再为镜头方案追问。
- **钩子他会自己定，且可能主动要「更夸张」、蹭对手名字**（2026-09-19：他先要「再夸张一些，体现快」，最后拍板「居然有比Codex的computer use更快速的agent！」）。流程：我按规则给有出处的版本 + 说清无出处版本的风险（没数据、画面没这个名字），**他拍板就照用，不再劝**。他的稿 = 新规则。
- 大改动先给方案：时间轴表 + 技术路线 + 改动范围，他说"可以/确认执行"再动手。
- 他给一串修改意见时，先**复述每条并说出背后原因**，再补自己更好的方案，再执行。（"不要只改表面，要理解我为啥这么改"）
- 先出短预览再出整片：开场 5 秒 → 中间 5～10 秒试听 → 整片。他按秒级挑问题。
- 他说"直接渲染"时，指的是「别再纠结稿子了、往下走」，不是「跳过预览」——但也不要拿预览去堵他，边跑边把关键帧抽给他看。
- 手机端上传上限 30MB，整片只能桌面端看，发片段。
- **交付三条（2026-11-01 他改定，旧两条作废）**：
  - **画面.mp4**：画面 + 字幕，**不带任何音频**。
  - **口播.m4a**：纯人声。
  - **音效.m4a**：纯点缀音效。
  文件名**不带 A_/B_/C_ 前缀**，就用中文名。三条从 0 秒对齐、等长。做法：build 不传 BGM 渲一次出画面轨 + 口播（用 `out/voice.mp3`）；再 `NO_VOICE=1` 渲一次出音效轨（`-vn` 取音频）。
- **BGM 彻底不做（2026-09-20）**：他自己配乐，任何产出（成片、分轨、审核片段）都不混音乐。旧 tonight-hiphop/BGM_VOL 方案作废。
- **1.2 倍速是整体变速（2026-09-20 起默认）**：TTS 保持 +18% 正常渲染，渲完对成片 ffmpeg `setpts=PTS/1.2` + `atempo=1.2`（不变调）——画面、转场、动效、视频素材、音效与口播一起加快。**不是把 TTS 调到 +42% 只加语速**（那样动效常数和素材片段不跟着快，他明确说要"画面契合"）。两条交付轨都是变速后的。
- **不给 SRT、不给剪映导入包。** 他不用剪映做二次加工了。（旧版本这里写的是"交付带剪映导入包"，已作废。）
- **音效轨单独出（2026-11-01 起）**：人声和点缀音效分开两条（`口播.m4a` + `音效.m4a`），方便他自己分别处理。之前「纯音效轨彻底不做」作废。
- **口播轨永远要给，别等他问。** 口播人声是标配（现在和音效分开两条）。口播源是 `out/voice.mp3`，必须 1.2 变速 + `-af apad -t <成片时长>` 补静音对齐到和其他轨等长（口播通常比成片短 1～2 秒）。
- **审核片段照发**：开场 0-6s、中段 24-36s、结尾 52-60s，放 `out/review/`。他要手机上看关键段落（整片超 30MB 发不出去）。

## 文案习惯（从他多轮改稿里总结）
写法上：
- 口语、短句，一句 6～16 字（2026-09-19 从 8～20 收紧：他嫌整体节奏慢，平均 7.4s/镜头被打回，配合「4 秒红线」快节奏），用逗号顿号切开，不写书面长句。连接词能删就删。
- 直接点名，不用代词悬念。（"背后就是它"→"背后就是这个 GSAP"，"它"很 AI）
- 说事实不说比喻。夸张比喻一律去掉。（"刻进肌肉记忆"→"变成 AI 的默认写法"）
- 动词平实：不用"抄"，用"复用"；不用"炸锅/炸了"这类空喊。
- 数字要具体且是页面实时值：star 数、数量、时间，写稿时再核一遍。（skill 数写错过一次）
- 对观众无信息量的不说：协议名、安装命令这种"程序员都知道的"。要讲的是它到底长什么样、做出来什么效果。
- 每个卖点、每个痛点必须在 README/官网/issue 找到出处，找不到就删。（编过两个痛点被打回）
- 说到任何具体名字（公司、案例、用户），画面同帧必须出现那个名字。
- **口播改了品牌称呼，同帧画面原文也必须对上。** 口播说「猫厂」，截图里不能还写「阿里」。处理：藏 DOM，或换不含该字的镜头。英文包名、仓库路径另问，不要擅自改。
- 审核词替换：收费→收米，免费→免米。其他敏感词同理绕。
- 称呼观众"兄弟"，语气是同行分享，不是营销号。
- 术语用圈内说法：AI 编程工具一律叫 **agent**（不说"编程助手""AI 助手""coding assistant"）；同理 skill 就叫 skill，不翻译成"技能"。
- 名词要具体到不用转脑子：写「架构图」不写「图」，写「系统架构图」不写「系统地图」。他说"看不懂"通常不是词太专业，而是指代太泛。
- **别为了压缩而压缩**：卖点句宁可多几个字，也要让人一遍听懂。典型反面：把 4 个动作压成名词短语并列（`搜节点、追上下游、走精确路径、播故事`），每个都要观众自己补宾语——他会直接说"完全看不懂"。正确写法是给足主语和宾语，该展开就展开（`能搜组件、能查上下游、能点出两个组件之间的路径`）。
- 抽象收尾句一律删掉：`全按作者定义的关系来`、`只改相关的地方` 这种既没画面也没信息，说了等于没说。换成具体结果（`别的地方不动`）。
- 痛点句要落在具体动作上：写「还在手搓」不写「能信吗」。抽象判断不如具体动作扎人。
- 定位句必须有主语 + 口语推进（`它是…它读完仓库就出图`）。无主语的功能标签堆叠 = 生硬，会被打回。字数与自然度冲突时保自然度。

结构上：
- 钩子一句打受众正在忍受的痛，≤8 字，可反问；第二句承接（"那就不要错过这个开源项目"这类）。**钩子和承接句都要上字幕**（2026-11-01 起，不再写 `nocap`），画面大字 `title` 仍用钩子短句。
- **结尾改短 CTA（2026-09-19 他推翻旧固定长 CTA）**：只留「感兴趣的兄弟快去冲吧」一句，压在最后一个产出物镜头上直接收；点赞/关注/评论胶囊条整个去掉（build 用 `CTA_MINIMAL=1`）。旧长结尾「想试试的兄弟赶紧冲。记得点赞关注…下期再见」已作废。
- **画面产出物优先（2026-09-19 定的方向）**：项目有真正的产出物（官方宣传片、成片、demo 效果）时，画面聚焦产出物「直达效果」；GitHub 代码/README 文字画面压到最少（报名 repo/star + 背书名字同帧这类必须的，合计 ≤10s）。**口播和画面解绑**：口播可以讲技术（HTML/GSAP/确定性渲染），画面同时放宣传片效果段，不必技术句配技术页。
- 总长 40～70 秒，卖点 3～6 个，内容够硬比短重要。

## 画面
- 主色唯一 **#00C3D0**，贯穿关键词、花字、画重点、徽章、CTA；`BRAND` 可覆盖，但一期只用一个色。
- 不用箭头贴纸。画重点两形态：手绘粗糙框（图形/按钮/数字/深色页）、划词蓝色高亮（浅色页文本段落）；框都贴合 DOM 测出的 bbox，不手摆。
- **叠加组件要「网感」不要「规整」**（2026-09-19 他打回过规整版任务卡：「太规整了，不是很有网感」）：贴纸风 = 黑描边 + 不规则圆角 + 每张歪斜错落 + 盖章式砸入 + 小晃动。新做花字/卡片/角标类组件时默认往这个方向走，别做成整齐的 UI 卡片。
- **贴纸要大、有冲击感，且必须走避让机制**（2026-09-19 连改三版后定的，前两版「太小/太保守」都被打回）：贴纸类组件（任务卡/序号徽章）不许固定位置，`placeStickers()` 按当前镜头 bbox 的屏幕投影挑空白更宽的一侧贴，组内间距/缩进带抖动（故意不规则）。**尺寸优先于避让**：侧边放不下时整组挪到重点区下方/上方，而不是缩小；轻微压到非重点内容的边缘是允许的（抖音贴纸常态），只有横竖都放不下才缩（下限 0.8）。定稿样式：主色底 + 黑字 72px + 白色割纸边(box-shadow 0 0 0 9px #fff) + 黑硬投影 + 砸入时画面震一下。新增贴纸类组件必须接这个机制，不许写死坐标。
- 画重点必须等被框的内容出现之后再画（录像等 bbox_t，静态等推镜结束）。
- 口播与画面字级对齐：镜头切换、画重点、花字绑到关键词出现的那一帧，不是整句开头。
- 开场不能"干"：用仓库最有辨识度的一屏做故障风进场，不要纯色底大字。
- **开场大字用 `title`，口播用 `text`，两者可以不等长。** 口播可以是整句，画面大字必须短到圈得住。长标题会折成两行。
- **开场标注是圈住整段大字，不是底部一条线。** 两行标题必须整圈框进去。`build.mjs` 按标题实际 bbox 画圈，不要写死下划线路径。
- 花字不重复画面原文；一期 2～4 个。
- 静态镜头目标放视口 42% 高，底部留字幕；字幕 ≤18 字分段，不切拉丁词/数字/关键词。
- **字幕必须带黑底**：纯黑 `rgba(0,0,0,0.8)`、无圆角、padding 上下 6px 左右 12px。底色**随内容包裹**，不铺满整行——打字机是逐字出的，底宽要跟着已显示的字一起长，否则第一帧就是个空的大黑条。光标消失后底色收回到文字右边缘，别在右侧留空白。
- 动效走 GSAP（SplitText/CustomEase/ScrambleText），要"高级感"，不要剪映模板感。
- CTA 样式与参考博主区分（描边胶囊 + 线描图标，不用彩色药丸和仓鼠贴纸）。

## 声音
- 口播 **edge-tts zh-CN-XiaoxiaoNeural +18%**，唯一默认。克隆音色他试过（IndexTTS2 太慢），两次说"不要用 index 了"；除非他主动提，不切。
- BGM 燃感/动感，默认 `design-to-promo` 的 tonight-hiphop，`BGM_VOL=0.32`（他两次要求"再大一点"到这个值），无口播处 ×1.5，末尾淡出。
- **开场（0 ~ hookEnd）完全无音效，只有口播和 BGM。** 两层都要清：① 专门的开场音效——闪入故障音、文字崩坏重拍、结尾硬切 whoosh，整块删掉；② 恰好落在这个时间窗里的点缀音效（切镜 whoosh、画重点划笔）也一并丢弃，因为那段画面被故障层盖着，切镜和画重点都看不见，配上音只会显得莫名其妙。他先让把闪入音减半，再要求整段去掉。
- **上一条只管开场。** 点缀音效层的规则本身不变，hookEnd 之后照原样全部保留。
- 点缀音效要种类丰富：关键词 pop 变音高、徽章 tick 递增、画重点划笔、切镜 whoosh、数字 coin、花字 hit+chime、CTA 三种 ding。明显的每 2～3 秒最多一个，全部低于口播 10dB。
