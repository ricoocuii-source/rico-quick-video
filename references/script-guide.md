# 口播稿指南（通用）

## 骨架（按顺序，时长是经验值）

| 段 | 时长 | 说什么 | 画面 |
|---|---|---|---|
| 钩子 | 1.5～2s | 受众的痛，一句反问；或大厂背书 | 开场库底图 + `title` 大字（圈住整段） |
| 承接 | 0～2s | 痛点钩子用"那就不要错过这个开源项目"；悬念/报名型钩子可以省掉承接直接报名 | 同上 |
| 报名 | 3～4s | 拆短句快组合：「记住这个名字X」（仓库名 1.5s）→「已狂揽 N 万 star」（star 1.5s）。钩子已点名定位时不重复 | 仓库标题 → star（counter），两跳 |
| 它是什么 | 4～6s | 定位拆成 2～3 个短句，每句换一跳 | README 同页跳切（定义→代码→结果） |
| 卖点 ×3～6 | 每个 2～5s | 一句一个，动词开头，带一个可高亮的关键词 | 每个卖点至少一个视觉变化 + 画重点/花字/徽章三选一 |
| 反差/福利 | 2～4s | 只在有事实支撑时做：曾经收米现在免米、大厂开源、刚开源就 N 万 star | 出处原文划词 |
| CTA | 1.5s | 短 CTA「感兴趣的兄弟快去冲吧」一句（2026-09-19 起，旧长结尾作废） | 压在最后一个产出物镜头上直接收（CTA_MINIMAL=1），无胶囊条 |

**节奏红线（与 shot-guide 同一条）**：按 6 字/秒排时间轴，任何画面超 4 秒无变化就加 cue 或拆句；每句至少 1 个 cue，超 5 秒的句子至少 2 个。

卖点段里如果有并列的 3 项（功能列表、支持的平台），用 `badges` 做序号徽章，比连说三个词好看。

## 钩子六选一（按项目挑，默认第一种；4~6 是 2026-09-19 对标「今天学点啥？」后 Rico 拍板加入）

1. **痛点反问**：目标用户正在忍受的事，≤8 字。例：`vibecoding太丑？`、`前端动效还在手写？`、`还在手搓 Agent？`
2. **反差数字**：项目页上真实的数字对比。例：`3 天 2 万 star`、`一个文件替代整个框架`
3. **大厂背书**：README 里有明确的知名用户/来源时。例：`宜家官网都在用的库`、`阿里内部正在用的 AI 代码审查工具`
4. **条件筛选**：用「如果你经常做X」先筛出受众再给结论，适合工具/库类。例：`如果你经常做前端，这个开源图标库建议直接收藏`
5. **悬念评价**：一句轻评价吊住，第二句必须立刻给出「是什么+能干什么」，不许拖。例：`这个 skill 有点东西`
6. **圈层呼告**：只用于模型/大事件资讯题材。例：`兄弟们，模型圈迎来重大更新`。普通项目速览不用。

**大厂背书钩子不能再接「那就不要错过」。** 钩子已经点明是什么工具，「错过这个开源项目」没有推进。改成：谁在用 → 现在能用了（如「现在开源了」）→ 报名。报名句不要再重复钩子里的定位。

开场大字用 `title`，口播用 `text`。`title` 可以短于口播整句，必须短到圈得住。

不用的钩子：`XX 圈炸了`、`这个项目太强了`、任何不指向具体事实的感叹。

钩子还有两个硬要求（Rico 改稿时明确过）：
- **对象要具体**：说「架构图」不说「图」，说「agent」不说「AI」。泛化名词观众得先转个弯对上号，等于钩子白写。
- **痛点落在动作上**：说「还在手搓」不说「能信吗」。抽象判断（可不可信、好不好用）不如具体动作（手搓、复制粘贴、来回改）扎人。

## 每类句子的写法

- 报名句固定式：`记住这个名字，{项目一句话定位}，在 GitHub 已狂揽 {N} star。` cues：`记住`→仓库名画重点，`{N}`→切到 star 镜头画重点。
- 定位句：`它是什么 + 给谁用 + 最亮的一个效果`，不超过 25 字。**必须有主语 + 口语推进**（`它是…你把…就出来了`），不能写成无主语的功能标签堆叠——Rico 一眼就判「生硬」。字数与自然度冲突时，保自然度。
- 卖点句：`动词/场景开头 + 具体名词 + 结果`。例：`官方 demo 库几百个效果，滚动触发、磁吸按钮、横向画廊，直接复用。`
- 痛点句：`专治 + 具体症状`，症状必须是 README/issue 里写的。例：`专治两个老毛病：React 里动画不清理一切页就内存泄漏；布局一变 ScrollTrigger 就错位。`
- 福利句：`曾经…现在…` 反差结构。
- **负担免除句**（每期至少 1 个，放在定位或卖点之后）：`你不用X，也不用Y`，X/Y 是用户原本要干的具体动作。例：`不用自己画图标，也不用从零写动画`、`不用自己去调图层，也不用研究一堆复杂参数`。这是把「工具功能」翻译成「用户省事」的固定手法。
- **通俗翻译句**（跟在最技术的那个卖点后面）：`简单来说就是…` / `也就是说…`，一句人话说结果。例：`简单来说就是原本一张静态图，直接有了点动起来的感觉`。一期最多 1~2 个，别句句都翻译。
- **数字三连**：并列的数据卖点连续快报、不逐个解释（`代码搜索最高压缩 92%，事故排查省 92%，issue 分流省 73%`），报完补一句质量兜底（`而且压缩之后答案质量基本不变`）。每个数字都要有出处。

## 卖点三条件（缺一不写）

1. **有出处**：README / 官网 / 官方博客 / issue 里能找到原话，写稿时把 URL 记在 script.json 的 `src` 字段。
2. **能定位**：页面上有一个 DOM 元素能框住它（标题、段落、卡片、代码块），这样才能截图和画重点。
3. **一句话说得清**：≤ 25 字说不清的卖点，要么拆成两个，要么删。

## kw / cues 设计

- `kw`：每句 1～3 个高亮词，必须是"看到就懂"的名词或数字，不高亮虚词和动词。
- **别把 agent 自动干的事写成用户负担**：写稿时任何暗示「用户要手工做什么」的措辞（描述、整理、导出、上传）都要回查 README 确认。Rico 一眼就会问「这个需要用户自己弄吗」。
- `cues[].at`：写句子里的**前几个字**（唯一即可），build 用它找字级时间。
- 每句最多 2 个 cue；镜头切换（`shot`）和画重点（`mark`）可以同一个 cue；花字（`sticker`）放在句子后半段的高潮词上。
- 一句里既有画重点又有花字时，让花字晚 0.5s 以上，避免同时抢注意力。
- 花字文案 2～5 字，是这句卖点的浓缩，不能是画面上已有的原文。
- `badges` 只用在画面本身没有那三项文字的镜头（官网 hero、demo 页）。README 镜头别挂 badges：徽章固定在左侧 110px，会盖住正文；README 列表本来就把三项写着，画重点框住列表就够了。

## 写完自检

- 通读一遍：有没有"它/这个东西/背后"这类代词悬念？有没有比喻？有没有编的数字？
- 每句都能对应一个镜头 id？镜头里能框到东西？
- 总字数 ÷ 6 ≈ 口播秒数（edge-tts +18% 实测 6.0～6.2 字/秒，两期都是），成片再 +1～2s。控制在 40～70。用 5.3 算会高估 15%，写稿时别为此砍卖点。
- 官网数字和 README 不一致时，口播跟 README，画面别卡在冲突数字上。
- 审核词替换过了？结尾是短 CTA 一句、压在产出物镜头上？
- 钩子若是大厂背书，承接句是推进（「现在开源了」）而不是「那就不要错过」？报名有没有跟钩子撞车？
